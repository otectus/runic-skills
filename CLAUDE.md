## Project Structure
```
src/main/java/com/otectus/runicskills/
  ├── mixin/           — Mixins (85 total: 5 client, 80 common)
  ├── client/vfx/      — Power proc presentation (descriptor, manager, glyph particle, sound cap)
  └── ...              — Skills, perks, config, commands, GUI, events
src/gametest/java/          — Forge GameTests (capability lifecycle, config authority, Power eligibility).
                              Own source set: needs a real server, so it cannot live in src/test.
src/tomCompat/              — Optional T.O. companion. Explicit `tomCompatJar` builds a separate
                              reobfuscated jar under build/compat-libs; never bundled into core.
src/legendarytabsApi/java/  — Hand-written signature mirror of the Legendary Tabs 2.0 API.
                              Compile classpath only; never shipped. See docs/BUILD_REPRODUCIBILITY.md.
src/customnpcsApi/java/     — Hand-written signature mirror of CustomNPCs' inventory-tab classes.
                              Compile classpath only; never shipped.
src/generated/resources/    — Declared as a resource root by build.gradle. Currently EMPTY: there is
                              no GatherDataEvent handler, so the `runData` run config produces nothing.
src/main/resources/
  ├── META-INF/mods.toml
  ├── runicskills.mixins.json
  ├── assets/runicskills/   — lang, models, textures (incl. generated power/ and particle/ sets)
  └── data/runicskills/     — block tags, a worldgen-structure tag, and the
                              `runicskills:affected_by_magic_resistance` damage-type tag that
                              Magic Resist is defined by and packs can extend
```

## Key Dependencies
- **YACL** (3.5.0) — config UI (optional, client-only). Server-safe code paths use plain Gson (`com.otectus.runicskills.config.storage.ConfigHolder`); the YACL UI lives in `client/config/`. The `:checkSidedImports` lint forbids YACL executable-class imports outside `client/config/`.
- **KubeJS** (2001.6.5) — scripting integration (optional)
- **Ars Nouveau** — magic system integration (optional)
- **Apothic Attributes / Apotheosis** — attribute system integration (optional)
- **Irons Spellbooks** — spell system integration (optional)
- **MineColonies** — colony building integration (optional, compile-only via LDTTeam Artifactory `com.ldtteam:minecolonies:1.20.1-1.1.1276` with Structurize, BlockUI and Domum Ornamentum on the compile classpath). The integration class loads through `RunicSkills.tryLoadIntegration("minecolonies", …)`; the `@Pseudo` mixin `MixPathingStuckHandler` is gated in `RunicSkillsMixinPlugin`.
- **L2Tabs / Legendary Tabs** — inventory tab integrations (optional, compile-time only). Neither has a public Maven coordinate, so both compile against minimal in-repo API surfaces and a fresh clone needs no manually supplied jar: Legendary Tabs `1.20.1-2.0` via the `legendarytabsApi` source set (`src/legendarytabsApi/java`, compile classpath only, never shipped), L2Tabs `0.3.3` via the tracked stub jar `libs/l2tabs-0.3.3.jar`. Both register through a probe-and-reflection facade (`LegendaryTabsIntegration.registerClientTab()` and `L2TabsIntegration.registerClientTab()`) so API breaks degrade to the built-in strip instead of failing mod load. For L2Tabs and Legendary Tabs stubs, calling an upstream method the stub does not declare is a compile error by design; add the signature to the stub and re-check it against the real jar.
- **CustomNPCs** — optional, compile-time only via the `customnpcsApi` source set (no Maven coordinate; the real jar is not tracked). `CustomNpcsIntegration` probes the real classes reflectively; the client integration (subscribed only after the probe passes) attempts to insert the Skills tab into CustomNPCs' strip where one exists, and reports per frame whether the insertion succeeded on the screen being drawn. A screen where CustomNPCs has no strip falls back to Runic Skills' built-in strip per-screen, rather than suppressing the strip entirely. The tab is inserted at first render (`ScreenEvent.Render.Pre`, adding the widget through Forge's SRG-aware `ObfuscationReflectionHelper` rather than a mixin accessor, whose generic target produced no refmap entry) rather than relying on `ScreenEvent.Init.Post` ordering, because CustomNPCs' own `Init.Post` handler is also `LOWEST` priority and runs in registration order, which this mod cannot influence; inserting at render-time removes the dependency.
- **MixinExtras** (0.4.0) — used by ten mixins: `MixItemStack`, `MixGrindstoneMenu`, `MixPlayerAction`, `MixAbstractContainerMenu`, `MixTinkerStationBlockEntity`,
  `MixExperienceOrb`, `MixModifiableBowItem`, `MixModifiableCrossbowItem`, `MixThrowingModule`,
  `MixToolHarvestLogic`. Declared as an annotation processor and a jar-in-jar dependency. Forge
  does not ship MixinExtras, so `jarJar` produces the distributable `runicskills-<version>.jar`
  and the plain `jar` task produces `runicskills-<version>-slim.jar`; this one dependency is the
  entire jarJar payload.
- **Tinkers' Construct / Mantle** — native tool integration (optional, compile-only via SlimeKnights Maven `https://dvs1.progwml6.com/files/maven/` for groups `slimeknights` and `slimeknights.mantle`). Stable 1.20.1-3.11.2.166 and 1.11.97 are compiled against; 3.12 is recognised but runs in conservative mode. Loaded through `RunicSkills.tryLoadIntegration("tconstruct", "com.otectus.runicskills.integration.tconstruct.TConstructBootstrap")`; modifiers registered via MOD-bus subscription within the bootstrap. Tinkers'-targeting mixins in `mixin/tconstruct/` use string targets and are gated in `RunicSkillsMixinPlugin` on presence + profile (3.11 only) + config flag `enableTConstructIntegration`. The class-level `remap = false` is correct — class names are never obfuscated — but it makes every *member* reference literal, which is only right for Tinkers'-declared members (e.g. the nested `@At` on `ModifierUtil.getInaccuracy`, which states `remap = false` explicitly). A member Tinkers' inherits or overrides from vanilla (`releaseUsing`, `tryPickup`, `getItem`, `removeItem`, `removeItemNoUpdate`) ships SRG-renamed inside Tinkers' own jar, so its injector must declare `remap = true` with the selector qualified by its full descriptor, so the annotation processor emits an SRG refmap entry. Dev and GameTests run Mojang-mapped and cannot catch a wrong verdict; `checkMixinRemapping` (wired into `check`) does, failing the build in both directions, and also enforces `require = 0, expect = 1` on every injector in this package. GameTests under `src/gametest/.../tconstruct/` are registered by `TConstructGameTests` without `@GameTestHolder`, so they load only when Tinkers' is present. Runtime profile selection via `-PtinkersProfile=stable|beta` (default: off, M0 baseline).

## Terminology
- **Aptitudes** = the skill categories (what players see as "Skills")
- **Skills** = individual abilities within aptitudes (what players see as "Perks")
This naming is internal — the player-facing UI uses "Skills" and "Perks"

## Conventions
- Registration: DeferredRegister on MOD bus
- Config: server-safe `ConfigHolder<T>` POJO + JSON5 storage; YACL UI is a client-only adapter (`client/config/YaclConfigUiBuilder`) reached via reflection from `ConfigHolder.generateGui()`
- Mixins: declared in `runicskills.mixins.json`. Plain SpongePowered Mixin — `@ModifyReturnValue`
  is used in `MixGrindstoneMenu` and `MixItemStack` (the `getMaxDamage` hook for Tinker's Touch bonus durability)
- Events: FORGE bus for gameplay, MOD bus for registration
- Access Transformers: none (disabled in build.gradle)
- Optional-mod integrations: load via `RunicSkills.tryLoadIntegration("modid", "FQCN")` so the integration class never enters the main constant pool. Client-side optional integrations (Legendary Tabs, L2Tabs, YACL UI) use a method-reference indirection from `ClientProxy` to avoid JVM-verifier eager-resolution.
