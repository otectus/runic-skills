# Perk effect-coverage backlog (machine-checked by PerkEffectCoverageTest).
#
# THIS LIST IS EMPTY, AND THAT IS THE POINT.
#
# Every name that used to appear here was a perk registered in RegistryPerks with a config value, a
# texture and a tooltip, and no runtime effect site at all — 340 of them at the 1.3.8 audit, 129
# still left when the 1.10 audit re-counted them (RS10-004). As of 2.0.0 there are none: every
# remaining entry was either implemented against the mechanic its tooltip describes, or removed
# outright because the mechanic it described does not exist in this build and could not be reached
# from it. The removals and the reasoning behind each are recorded in docs/PERK_AUDIT.md and in the
# 2.0.0 changelog.
#
# The rules PerkEffectCoverageTest enforces are unchanged, and they are what keeps this file empty:
#   1. A registered perk MUST either have an effect site or appear here — so a NEW perk cannot
#      silently join the inert pile. Adding a line here is a deliberate, reviewable act.
#   2. Once a perk gains an effect, its line MUST be deleted (the test fails on a stale entry).
#   3. Entries must name real registered perks (no typos / dead names).
#
# If you add a line to this file, say why on the line above it. An entry with no explanation is a
# perk somebody gave up on quietly, which is exactly what this file exists to prevent.
#
# Blank lines and #-comments are ignored.
