# 2.1.2 audit: changes, evidence and remaining work

Unpublished development work against baseline `ee17728` (2.1.1). The
[prioritized plan](AUDIT_PLAN_2026_09.md) was written before implementation.
The current code and `CLAUDE.md` governed the review; earlier audit claims were
checked against their actual consumers.

## Coverage

The [generated current trace](CONTENT_TRACE.md) inventories all **10 skills,
507 perks, 38 passives, 111 Powers and 9 owned stat attributes**. Each entry links
definitions/defaults, English behavior and executable consumers. The shared routes
cover progression authority, gates, persistence, disabled/dormant content, attribute
reconciliation, client presentation and optional loading. `tools/content_trace.py`
now indexes references once and preserves source line numbers; it leaves the
historical 2.1.0 trace intact.

Domain reviews supplement that inventory:

- [Progression/combat](AUDIT_PROGRESSION_COMBAT_2026_09.md): effective versus saved
  ranks, XP accounting, skill/stat routes, Power consumers and combat lifecycle.
- [Crafting/Tinkers](AUDIT_CRAFTING_TINKERS_2026_09.md): committed transactions,
  conservation, native repair/wear, workshop ownership and add-on gates.
- [Integrations/UI](AUDIT_INTEGRATIONS_UI_2026_09.md): optional providers, mana
  exchange, interfaces, artwork and supported/unimplemented integration boundaries.

A consumer reference is not proof of every upstream event or every spell/weapon
combination. The validation record below distinguishes executed profiles from
source inspection. Existing icons were retained: the generator check verified
**698 unique native icons**, without missing art, duplicate pixels or partial alpha.

## Compatibility

Version **2.1.2**, protocol **15**: the artwork packet requires updating client and
server together. The build's version/protocol checks enforce matching documentation.
No progression identifiers, paid tool upgrades or saved allocation fields are
deleted. Dormancy replaces ineffective selections without erasing them. The
[migration guide](MIGRATING_TO_2.1.2.md) describes the balance and configuration changes.

## Remaining limits and in-game checks

- Full visual client QA remains required: GUI scales, resource-pack reload/fallback,
  remote-server joins/disconnects, tooltip wrapping and native mod screens.
- The existing four-mod spec still has separate work for automatic family equipment
  gates and client rule synchronization. Current native triggers and explicit
  boundaries remain documented; this pass does not label those spec items complete.
- `Title.HideRequirements` is startup metadata and is not yet an authoritative
  client title-configuration snapshot. Custom title visibility may differ across
  differently configured peers or after config reload. Earned title/save authority
  is separate from that presentation limitation.
- Advancement title conditions retain their legacy positive-completion semantics:
  the expected value/comparator are not a supported negative-completion predicate.
- Crafting conversion detection covers direct static reversible recipes, not every
  arbitrary custom or multistep recipe graph. Recycling rolls remain deterministic
  per player/item/recipe, rather than per physical item. Lore Mastery's grindstone
  XP attribution still uses an open-menu/fresh-orb heuristic; exact upstream origin
  attribution is separate work.
- FTB non-sticky team tasks still need explicit semantics for mixed member
  progression. Other positive ISS mana grants retain the broad regeneration
  interpretation; this pass isolates the priced Unified Arcana refund only.
- Approximate Power implementations remain explicitly described by
  `CONTENT_STATUS.md`. The audit does not substitute their original design for the
  shipped mechanic or promise exhaustive upstream spell/add-on compatibility.
- Existing Gradle/Forge annotation and deprecation warnings remain; build checks
  and real-server runs, not absence of warnings, determine validation success.

No release, push, or deployment to a player's modpack has been performed.
